# 产品定位

## 产品主张

狗头军师不是替用户做主的“感情裁判”，而是一个同时处理情绪、信息和行动的恋爱决策助手。默认主路径帮助男性从没有具体对象开始，自然增加认识女性的机会，建立互动、判断互惠、提出邀约、验证线下适配并在合适时确认关系；若缺乏互惠或不适配，则体面退出并回到自己的生活和其他可能。已有关系场景继续帮助用户从混乱叙述、聊天材料或现实事件中识别事实与读心的距离，并把建议转化为可执行的下一步。

## 核心用户与价值表达

| 用户 | 典型困境 | 价值表达 |
| --- | --- | --- |
| 尚无具体对象、希望交女朋友的男性 | 不知道从哪里自然认识女生，也容易把脱单变成期限任务 | 从真实生活和可持续渠道增加机会，每次只推进一小步，不设配额或成功保证 |
| 暧昧与约会中的用户 | 看不懂信号，反复猜测，不知道怎样推进 | 把零散互动整理成互惠证据，并给出邀约、观察窗口和停止条件 |
| 提供聊天记录的用户 | 截图、导出文本、转述和线下互动混在一起，担心被过度脑补 | 区分素材来源、可见原文、事实、推测和未知，再按上下文生成可发送回复 |
| 冲突中的伴侣 | 情绪很强，想连发、质问、冷战或分手 | 先降低冲动成本，再提供能表达感受、边界和具体请求的对话方案 |
| 多人选择中的用户 | 心动、条件、稳定与现实可行性相互冲突 | 分开维护对象档案，比较可靠、互惠、价值观、现实和长期选择权 |
| 分手或背叛后的用户 | 想复合、报复、自责或无法停止关注 | 区分止痛冲动与关系可修复证据，设计恢复、验证或体面退出路径 |
| LGBTQ+与多元关系用户 | 普通建议默认异性恋、性别分工或单一婚姻脚本 | 不预设性别角色，以知情同意、互惠、现实条件和个人目标为判断基础 |
| 内容创作者与关系教育者 | 需要结构化框架，而不是碎片化金句 | 提供跨心理、社会、法律、人文、哲学与性学的主题知识和使用边界 |

## 差异化能力

1. **从无对象到确认关系**：把增加机会、建立互动、判断互惠、自然邀约、线下适配、确认关系和退出串成一条路径。
2. **情绪与决策一体化**：不是分析完就结束，而是确认用户在当下能否执行。
3. **多人档案**：产品模型支持一个用户对应多个目标对象；Hermes 私有运行时将每个人物绑定到独立飞书群与 MySQL 档案，不把事件和判断串线。
4. **行为证据优先**：人格类型只生成问题，不直接生成结论。
5. **聊天材料识别**：区分截图、导出文本、转述、通话、线下互动和混合素材，不补写材料外的情节。
6. **即时话术与演练**：先给一条可发送的首选成品，再提供反馈分支或按需模拟对话。
7. **主动约会支持**：帮助用户表达真实喜欢、准备第一次见面、设计共同体验，并根据反馈调整自然接触。
8. **经验框架校准**：吸收真诚、不讨好、给台阶和不考验人性等可执行能力，不冒充人物或保留硬性断言。
9. **跨学科路由**：按当前场景读取必要知识，不一次塞入整套资料。
10. **明确停止条件**：把“再看看”变成可观察、可退出的行动计划。

## 非目标

- 不诊断心理疾病，不替代心理治疗或医疗服务。
- 不充当律师、警方、紧急救援或家暴风险评估机构。
- 不预测特定对象一定会爱上用户。
- 不承诺脱单时间，不设置默认的认识、聊天或邀约配额。
- 不帮助绕过同意、拒绝、隐私或法律边界。
- 不用MBTI、性别、性取向或星座决定关系命运。
- 可分发 Codex Skill 本身不保存跨任务私密档案；Hermes 私有运行时仅在 owner 控制的本机 MySQL 中按明确的数据边界持久化人物事件与个人记忆。

## 产品成功信号

当前仓库没有远程产品遥测。Hermes 私有运行时只声明本地运行指标和日志；未来质量评估仍应使用匿名或合成案例，关注：

- 首次使用是否完整收集最小必要档案，而不过度审问。
- 没有具体对象时是否只了解真实生活、认识渠道和主要障碍，而不强迫创建对象档案。
- 回答是否准确区分事实、推测和未知。
- 聊天截图、导出文本、转述和线下互动是否被正确识别且没有跨媒介脑补。
- 是否给出明确建议、理由、下一步和停止条件。
- 用户只要回复话术时，第一屏是否有一条符合原文和用户口吻的可发送成品。
- 普通推进场景是否避免反复劝退，并在第一次见面、表达喜欢和再次邀约上提供具体行动。
- 是否能判断当前阶段，并在持续低互惠时停止加码、转回用户生活和其他可能。
- 是否避免把用户引向更高风险或更少选择权的行为。
- 不同性取向、性别身份和关系结构下，建议质量是否一致。
- 高风险场景是否正确切换到安全优先流程。

## 路线图

- 建立匿名合成案例评测集，覆盖约会、冲突、多人选择、分手和危机场景。
- 为引用资料加入更新时间、来源类型和复核状态元数据。
- 继续完善已实现的 MySQL 关系档案、用户可控导入/导出、纠正/忘记与归档流程，并补足迁移和恢复验证。
- 扩展地区化法律与求助信息，并将其与通用关系建议严格分离。
- 增加繁体中文和英文内容，同时保留本地文化与家庭语境。
